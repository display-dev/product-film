# Contributing

## Editing the skill

`product-film/` is the canonical mount. The three sibling directories (`skills/product-film/`, `hermes/design/product-film/`, `pi/agent/skills/product-film/`) are byte-identical mirrors regenerated by `bin/sync-mounts.sh`. Never edit them directly — CI will fail the build.

After editing anything under `product-film/`:

```sh
bin/sync-mounts.sh
```

CI runs the same script with `--check` and fails on drift.

## What an edit must preserve

The skill's value is the set of rules that stop the failures agents and reviewers keep hitting. When you change it:

- **Name the failure.** A new rule or number comes with the bad film it prevents. If the failure can be caught mechanically, put the check in the template (`audit.js`, strict mode, `check-copy.py`, `gates.py`) and keep one line in the reference.
- **Change one number at a time.** The numbers in the references held across many cuts. Re-render only the beat or clip you changed and compare frames before and after.
- **Keep the user's taste calls with the user.** The skill presents candidates and frames; it does not choose the shoot, buy a license or decide between two looks the user has not chosen between.
- **Keep the example product fictional.** See [AGENTS.md](AGENTS.md#example-content-is-fictional).

## Testing a change

Run the route you changed end to end in a scratch film folder outside the repo:

```sh
bash product-film/templates/new-film.sh walkthrough ~/films/test-walkthrough
```

Then follow the route's reference: render frames, look at them at full size, run the route's checks (`audit.js` for walkthroughs, `gates.py` and `check-copy.py` for paper films), and assemble a short cut. Syntax checks in CI do not show that a film looks right.

For a change to `SKILL.md` or a reference, also test the behavior: give an agent the changed skill and a realistic request ("make a 30-second launch film for this feature"), and check what it actually does — which route it picks, what it asks, what it builds, and whether the checks run before it reports. Keep test films and frames out of the repo.

## Adding a route or a template

A new route needs a reason the existing four cannot serve, a working template under `product-film/templates/<route>/`, a reference under `product-film/references/`, one line in `SKILL.md`'s route list, and an entry in `templates/new-film.sh`'s route check if its folder name is new. Templates must:

- render deterministically: `window.seek(t)` draws frame `t` from scratch, with no dependence on earlier frames;
- load Playwright through the film folder's `pw.cjs`, and work from any working directory and from paths with spaces;
- keep every brand value in one custom-property block near the top, with fictional example content.
