# AGENTS.md — instructions for AI coding agents working in this repo

This repo is the source for the `product-film` agent skill. Edits land under `product-film/` (the canonical mount); the three mirror mounts under `skills/`, `hermes/design/` and `pi/agent/skills/` are regenerated by `bin/sync-mounts.sh`. **Never edit the mirrors directly** — CI fails on drift.

## Editing workflow

1. Make changes only under `product-film/`.
2. Run `bin/sync-mounts.sh` to propagate.
3. Commit the canonical change and the mirror updates in the same commit.

## Skill authoring split

- **`SKILL.md` is the router and the shared procedure.** It picks the route, lists the inputs to settle, and holds the rules every route shares (product fidelity, review discipline, what the skill does not do). Route-specific numbers, engines, gotchas and failure modes live in `references/`.
- **One home per rule.** A rule lives in `SKILL.md` or in one reference, never both. Repeated rules drift.
- **References defer to `SKILL.md`.** A reference applies the shared rules, then adds only its route's procedure, numbers and failure modes.
- **Templates carry the working code.** A rule that a template can enforce (a pointer-rest audit, a strict mode that throws on a missing shot, a copy check) belongs in the template, with one line in the reference that names the check.

## Constraint discipline

Every rule must name the bad film it prevents: a stuck pointer, a one-frame flicker, text that goes soft at 2×, a caption that dissolves into another caption, a claim the product cannot back. "Consistency" alone does not count. The numbers in the references held across many review rounds; change one at a time, and record the reason when a number changes.

## Example content is fictional

Every template's example product is **Tidewell**, a fictional shared-docs app (`app.tidewell.example`, people at `@example.com`). Keep examples fictional: no real products, logos, people or companies in templates, fixtures or docs. Third-party products that appear in a user's own film are named in text, never shown as logos, unless the user has the right to show them.

## Repository layout

```
product-film/                  ← canonical mount, the only directory humans edit
├── SKILL.md                   ← router + shared procedure
├── references/                ← per-route numbers, engines, gotchas, lessons
└── templates/
    ├── new-film.sh            ← starts a film folder for a route
    ├── common/                ← copied into every film folder (Playwright loader, capture library, chart background)
    ├── cinematic/             ← Routes A and B: 3D camera beats
    ├── walkthrough/           ← Route C: pointer-driven walkthrough, plan-based render, audit
    └── paper/                 ← Route D: cut-paper collage engine, kit, capture harnesses, sound, review and delivery tools

skills/product-film/           ← mirror — npm skills (`npx skills add`)
hermes/design/product-film/    ← mirror — Hermes well-known
pi/agent/skills/product-film/  ← mirror — Pi / OpenClaw

bin/sync-mounts.sh             ← regenerate the three mirrors
.github/workflows/ci.yml       ← mirror check + JSON lint + shell, Node and Python syntax
```
